## L2 — Problem context

Redis is configured as an in-memory cache without persistence (no AOF, no RDB). On restart, all rate-limit windows reset to 0 and a coordinated burst can hit us for a ~30-second window. Not exploitable today but shows up on the security review checklist.

## L3 — Attempts / workarounds

- Enable AOF everysec — trade write latency for durability
- Move counters to a Postgres UNLOGGED table — cheap, still fast
- Add a startup 'grace' — reject all traffic for 60s post-restart

## L4 — Resolution / raw discussion

Discovered during rate-limiter load test — restarted Redis mid-run, counters vanished. Not a v1 blocker; parking as pre-GA hardening.
