## L2 — Problem context

Consumer uses log-compaction semantics and dedupes by (event_key, session_id). But a legitimate use case — same user retrying — reads as duplicate. Analytics undercounts retries which are themselves a KPI. Discovered when a replay showed 12% fewer events than the source topic.

## L3 — Attempts / workarounds

- Add a `retry_seq` field to event schema
- Consumer key on (event_key, session_id, retry_seq)
- Backfill last 7d of analytics with corrected dedup logic

## L4 — Resolution / raw discussion

Product manager flagged the KPI mismatch. Root-cause traced to the dedup key. Fix touches schema — needs a producer coordination.
