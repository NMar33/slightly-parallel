## L2 — Problem context

First full staging dry-run of the MySQL → Postgres migration showed every TIMESTAMPTZ value shifted by 1 hour. MySQL server was UTC, but pgloader converted assuming server local time (Europe/Moscow, MSK+3, but DST-adjusted to +4 for the affected dates). Critical because financial reports would be off by a day boundary for midnight-adjacent rows.

## L3 — Attempts / workarounds

- Pin session timezone to UTC in pgloader command file
- Add a spot-check assertion on 100 sampled rows after migration
- Escalate to the operator for approval of the fix

## L4 — Resolution / raw discussion

Caught in the dry-run — nothing shipped to prod. Fix landed in pgloader.conf. Adding a post-migration timestamp audit to the cutover checklist (g_b2).
